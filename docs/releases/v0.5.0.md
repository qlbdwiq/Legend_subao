# YOLO11 Detection and ByteTrack Tracking (2D)

기존 `v0.4.0`까지의 두 카메라 수신 기능을 그대로 유지하면서, 학습된 **YOLO11n** 모델로 드론을 탐지하고
**Ultralytics ByteTrack**으로 카메라별 추적 ID를 부여하며 **바운딩 서클**을 표시하는 2단계를 추가합니다.
이 릴리스는 2D 픽셀 좌표까지만 다룹니다. **3차원 좌표, 스테레오 삼각측량, 드론 간 거리, 충돌 위험 경고는 포함하지 않습니다.**
기존 `v0.1.0`–`v0.4.0` 태그와 릴리스는 그대로 보존됩니다.

## 첨부 파일

- `DroneCollisionDetection-v0.5.0-macos-arm64.dmg`: Apple Silicon (M1 이상)
- `DroneCollisionDetection-v0.5.0-macos-x64.dmg`: Intel Mac
- `DroneCollisionDetection-v0.5.0-windows-x64.exe` / `.zip`: Windows 10/11 x64 (CPU 전용 AI)
- `phase-01-camera-stream-v0.5.0.zip`: 개발용 Python 소스 (파일 이름의 `phase-01`은 기존 릴리스와의 호환을 위해 유지)
- `SHA256SUMS.txt`: 첨부 파일의 SHA256
- `drone-camera-android-v0.4.0-debug.apk`, `drone-camera-ios-v0.4.0-unsigned.ipa`, `drone-camera-ios-v0.4.0-xcode-project.zip`: 휴대폰 송출 앱.
  **`v0.4.0` 릴리스의 파일을 그대로 복사한 것**이며(SHA256 동일) 이번 변경에서 모바일 앱은 바뀌지 않았습니다. 서명 전 IPA는 그대로 설치할 수 없고 Xcode 프로젝트로 직접 설치해야 합니다.

**빌드·검증 경로:** macOS arm64 DMG는 개발 Mac에서 직접 빌드해 실제 `best.pt`까지 스모크 테스트했고, Windows EXE와 Intel Mac DMG는 GitHub Actions CI(Windows·Intel Mac 포함 전체 잡 통과)가 빌드한 파일입니다.
CI의 동결 앱 스모크 테스트는 카메라 두 채널 수신, torch·ByteTrack 런타임을 확인하며 **`best.pt`가 없어 실제 모델 추론은 하지 않습니다.**
따라서 **Windows와 Intel Mac에서 실제 모델로 추론해 본 적은 없습니다**(Intel Mac은 PyTorch 2.2.2 조합, 실제 Intel 장비 실행도 없음).
Apple Silicon 로컬 테스트 164개(실제 모델 포함)가 가장 폭넓은 검증입니다. 실제 드론 비행 검증은 없습니다.

학습된 모델 파일(`best.pt`)과 데이터셋은 **첨부하지 않습니다.** 프로그램의 **모델 불러오기**로 직접 선택합니다.
PyTorch가 포함되어 이전 버전보다 파일이 훨씬 큽니다(DMG 약 300 MB).

## 변경 내용

- **AI 탐지 패널:** 모델(.pt) 선택·다시 불러오기, AI 탐지 ON/OFF, 신뢰도·NMS IoU·추론 해상도·장치 선택,
  박스/서클/ID/신뢰도 표시 선택, 서클 여유 계수 조절(기본 1.2). 설정은 `ai_settings.json`에 저장되며 모델 경로를 코드에 고정하지 않습니다.
- **카메라별 ByteTrack:** 카메라마다 별도의 모델 인스턴스·추적 상태를 사용합니다. **카메라 1의 ID와 카메라 2의 ID는 서로 무관**합니다(대응은 3단계).
  일시적으로 놓친 드론은 마지막 위치를 그리지 않고, 다시 나타나면 `reacquired`로 구분합니다.
- **바운딩 서클:** 박스 대각선의 절반 × 여유 계수. 중심·반지름(px)을 화면에 표시하고, 카메라 ID·프레임 번호·수신 시각·ID·박스·중심·기본/안전 반지름·신뢰도·상태를 데이터로 제공합니다(`docs/ai-detection.md`). 기하 계산은 GUI와 분리된 모듈입니다.
- **영상과 분리된 추론:** 모델 로드·추론은 별도 스레드에서 실행하고 카메라마다 최신 프레임만 처리합니다. 처리 FPS, 추론 지연, 수신→결과 지연을 영상 FPS와 구분해 표시합니다.
  AI를 켜지 않으면 스레드도, torch 로딩도 없습니다. 모델 오류가 있어도 카메라는 계속 사용할 수 있습니다.
- Ultralytics의 온라인 확인·자동 설치·익명 통계를 끄고 설정을 앱 폴더에 둡니다.
- 의존성: PyTorch 2.15(Intel Mac은 2.2.2), NumPy 2.3.5(Intel Mac은 1.26.4), Ultralytics 8.4.212 고정. 기존 PySide6/OpenCV는 그대로입니다.

## 알아둘 점

- **라이선스:** Ultralytics는 **AGPL-3.0**이며 학습된 모델도 기본적으로 AGPL-3.0 대상입니다. 이 저장소의 자체 코드는 MIT이지만 Ultralytics를 포함한
  배포 파일에는 AGPL-3.0 조건(소스 공개 등)이 적용될 수 있습니다. 소스 ZIP을 함께 제공합니다. 상용·비공개 배포라면 Ultralytics Enterprise License를 검토하세요.
- **검증 범위:** Mock 엔진 테스트와 실제 `best.pt` 테스트를 구분했습니다. 실제 모델 테스트는 학습 이미지에서 잘라 만든 **합성 영상**이며 동작 확인용입니다.
  **실제 드론 비행, 실외 환경, 두 카메라 동기화, 거리 정확도는 검증되지 않았습니다.** 기존 학습 환경의 mAP 등은 기존 학습 환경의 결과입니다.
- **ID 한계:** ByteTrack은 외형 특징 없이 위치로 연결하므로 두 드론이 겹쳐 지나가면 ID가 바뀔 수 있습니다. 서클 여유 계수 1.2는 실험값이며 비행 안전을 보장하지 않습니다.
- **장치:** Windows EXE는 CPU 전용입니다(CUDA는 소스 설치에서 CUDA 빌드 torch로 사용 가능, 미검증). 자동 장치는 CUDA가 없으면 CPU를 선택합니다(작은 모델에서는 Apple MPS가 CPU보다 느렸습니다).
  Intel Mac은 PyTorch 2.2.2를 사용합니다.
- **신뢰할 수 있는 `.pt`만 사용하세요.** PyTorch 모델 파일은 불러올 때 코드가 실행될 수 있는 pickle 형식입니다.
- macOS 앱은 Developer ID 서명·Apple 공증이 되어 있지 않고, Windows EXE는 Authenticode 서명이 없는 개발 배포본이라는 점이 기존과 같습니다.
- 모바일 APK·IPA는 이번 변경과 무관하여 `v0.4.0` 릴리스의 파일을 계속 사용합니다.
- Intel Mac(torch 2.2.2) 조합은 CI의 스모크 테스트를 통과했지만, Rosetta 에뮬레이션 전체 테스트에서는 163개 통과·1개 실패(AI 처리 프레임 수 기준 미달)였고 원인은 조사하지 않았습니다.
